# TOEFL Slang Master - Pipeline Architecture

本项目由三大主线模块构成，它们不是孤立的功能，而是系统流转中的三个主要环节。

## 第一段：Content Parser (上游素材入口)

**定位**：输入型学习链路的上游。

它的职责不是做“漂亮笔记”，而是把原始内容（PDF、Markdown、TXT）转化为可学习、可复用、可下游消费的结构化对象。

- **输入**：PDF, Markdown, TXT, 纯文本片段等。
- **输出**：`SourceDigest`（供阅读材料价值摘要），`ExpressionCandidates`（供后续升级词卡的候选）。
- **主要行为**：提取文本、识别类型、分析句式/文化点/表达候选。
- **非职责**：不作整篇作文的打分、不做复杂的用户记忆排期。

## 第二段：Dictionary Pro (知识固化与转化核心)

**定位**：整个系统的表达升级核心与复用核心。

它把粗糙的表达转化为可复习、可迁移的原子化学习单元（词卡）。词卡稳定输出为 Markdown 和 JSON。

- **输入**：口语词汇、低阶词汇、外刊候选词、作文弱表达。
- **输出**：`ExpressionCard` (包含 translation, slang, alignment, frequency, analysis 以及 index.md 和 card.json)。
- **主要行为**：进行语域转化（Registry Conversion），对标学术/地道英语，对比近义词。
- **非职责**：不负责处理动态 GUI，不负责开发复杂的 SRS（间隔重复）算法系统。

## 第三段：TOEFL Coach (输出型诊断核心)

**定位**：输出型学习链路的诊断核心。

提取用户的写作弱点，将用户输出转为结构化诊断对象，以反馈至学习流水线中。

- **输入**：用户撰写的句子、段落或托福级别作文。
- **输出**：`WritingDiagnosis` (整体诊断及重写建议)，`WeakExpressionSet` (下游复用的弱表达集合)。
- **主要行为**：逻辑诊断、词汇诊断、句式诊断。
- **非职责**：不直接化身重写引擎代替用户写作，不负责词卡渲染，不过早管理长期记忆。

---

## 模块间的闭环流转 (Connector Layer)

这三个模块共同勾勒出两套主要的学习闭环：

1. **输入型学习闭环 (`Content Parser -> Dictionary Pro`)**
   从外刊文本中提取有效信息，筛选表达候选并自动制作高质量学习卡片。

2. **输出型纠偏闭环 (`TOEFL Coach -> Dictionary Pro`)**
   将作文诊断出的低级或错误词汇，通过字典模块转换为学术界或地道的美式表达。
