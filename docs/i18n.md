# TOEFL Slang Master - i18n (Internationalization) Rules

本项目面向华语学习者，天然需要支持多种语言（尤其是简体中文 `zh-Hans` 和繁体中文 `zh-Hant`）。然而，多语言支持必须严格遵循以下原则。

## 根本原则

**Locale（语言区域）仅为展示层概念，绝不是 Schema 层的概念。**

## 详细规范

1. **底层统一**
   所有的 JSON keys、Schema 字段名、枚举值 (Enum)、系统内部 ID 一律**保持纯英文**。

2. **语域标识统一**
   `targetRegister` 等运行时场景控制参数始终保持为英文。
   *示例：`toefl-writing`, `toefl-speaking`, `general-academic`, `daily-english`.*

3. **展示层本地化**
   Markdown 格式的说明文字、内容解释、标签文本、终端提示语可以根据用户设置的 Locale 动态切换。

4. **第一阶段支持语言**
   - 简体中文 (`zh-Hans`)
   - 繁体中文 (`zh-Hant`)
   - 英文 (`en`)

5. **严禁业务逻辑分叉**
   - 绝对**不要**让简体中文和繁体中文长出不同的业务处理逻辑。
   - 绝对**不要**因为 Locale 不同而分化出独立的 Prompt 流程系统。
   - 绝对**不要**让 Contract 形态、Enum 定义或中间对象的命名受到 Locale 的影响。
   - Locale 亦不能影响 Provider Runtime 解析策略或 Connector 层的 Mapping 映射规则。

## 总结

- **Contract/Schema** 强制全英文统一
- **解释性/指导性文本** 随本地化配置转换
- **内部流转逻辑** 不因 Locale 发生任何变更或分支
