# Output Rules (Markdown & JSON Sidecar)

本项目所有的生成产物必须遵守双产物落地原则，避免内容只停留在终端上。

## 产物构成

每次智能生成操作（抽取/诊断/转化），必须落盘为两份文件：
1. **`*.json` (Sidecar)**：包含未经格式化的、符合 Contract 定义的 JSON 实体（如 `ExpressionCard`）。供程序复用、批量处理。
2. **`*.md` 或 `index.md`**：易于人类阅读和复习的视图文件，基于统一骨架渲染而来。

## 统一目录结构 (`outputs/`)

系统根目录下的 `outputs/` 将成为所有持久化学习产物的汇总地：

```text
outputs/
├── content/              # Content Parser 的解析落盘
│   └── 2026-04-10-economist-article-slug/
│       ├── digest.json
│       ├── index.md
│       └── candidates.json
├── dict/                 # Dictionary Pro 的词卡库
│   ├── gonna/
│   │   ├── card.json
│   │   └── index.md
│   └── substantial/
│       ├── card.json
│       └── index.md
└── coach/                # TOEFL Coach 的诊断落盘
    └── essay-2026-04-10/
        ├── diagnosis.json
        └── report.md
```

## Markdown 输出统一样式

所有模块写入 Markdown 时的标题和布局风格应保持克制与统一：

1. **H1 标题**: `# [对象短名或标识]` 
2. **元数据 Quote**: `> Generated by TOEFL Slang Master | Module: xxx | Target: xxx`
3. **主属性表格**: `| 维度 | 内容 |` (如 Dictionary Pro 的翻译、俚语、评级)
4. **解析与评价**：`## 解析 / 分析`...
5. **JSON Sidecar 链接**: 在末尾附带 `[📦 源数据](./card.json) / [🔄 去复习](#)`

保持朴素，不要过度设计动态网页，以 Typora/Obsidian 最佳兼容性为准。
